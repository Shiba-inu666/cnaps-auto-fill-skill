# 表格处理流程

## 识别字段

在每个工作表逐一识别字段，不要只处理第一张表。常见开户行字段包括：

- 收款账号开户行
- 收款方开户行名称
- 开户行
- 开户行支行名称

常见目标字段包括：

- 收款银行人行行号
- 收款方联行号
- 人行行号
- 开户行大额行号
- 大额行号

特别检查模板错位：如果“开户银行（行别）”列出现 12 位数字，而“大额行号”为空，应先确认是否把行号填错了列。

## 批量处理

1. 保留原文件，默认另存为新文件。
2. 汇总所有工作表中不重复的开户行名称，并同时保留省、市、区县上下文。
3. 对每个唯一组合查询本地注册库，减少外部查询次数。
4. 精确匹配只把 `auto_fill_ready` 写入目标单元格；对 `verified_match`、`review`、`unknown` 自动使用大模型联网检索并打开原始记录核验。仍无专属行号时，默认独立查询最近已核验上级行，再以已核验总行为最后兜底，并以 `parent_fallback` 写入。不得把宽泛别名改成永久安全别名；`conflict` 不填。
5. 新支行按多来源规则搜索完整名称、地区、改名和上下级关系，满足规则后写回本地库，再重新查询并填值。模型回答和搜索摘要不算来源。
6. 不覆盖已有的不同值。把“原值与已核验值不一致”列入冲突清单，等待用户确认。
7. 付款、代发工资模板中的行号建议写成文本值，避免前导零、科学计数法或公式兼容问题。不要把公式留给银行上传系统计算。
8. 保持账号、证件号、电话号码等字段为文本格式，不改变原始值。
9. 完成后检查每一张修改过的工作表、筛选状态和隐藏行列，确认没有错位或漏表。

## 审计结果

生成独立审计表或同目录 CSV，至少包含：

| 字段 | 说明 |
|---|---|
| source_file | 源文件 |
| sheet | 工作表 |
| row | 原表行号 |
| input_bank_name | 输入开户行 |
| canonical_bank_name | 规范开户行 |
| cnaps_code | 12 位行号 |
| status | auto_fill_ready / verified_match / review / conflict / unknown |
| match_method | canonical_exact / approved_alias / alias_review / fuzzy / parent_fallback |
| source_1 | 第一来源直接链接 |
| source_2 | 第二来源直接链接 |
| checked_at | 核验日期 |
| fallback_scope | 无 / 最近上级 / 区域上级 / 总行 |
| risk_flag | 无 / 上级兜底 / 总行兜底 / 旧称 / 缺少支行地区 / 来源陈旧 / 冲突 / 未找到 |
| notes | 冲突或人工复核说明 |

只把开户行名称、地区和候选行号用于查询。不要把姓名、账号、银行卡号、身份证号、工资或手机号发送给外部查询服务，也不要写入本地行号库。

交付时必须在回复中汇总所有 `risk_flag` 不为“无”的行。即使兜底行号已写入，也要提示其不是已确认的具体开户网点行号。
